# Countryballキャラクターの作成・確認手順

更新日: 2026-08-19
対象: `src/scene/residents/` のキャラクター表示

この資料は、国旗模様と顔を持つCountryballキャラクターについて、現在の作成方法、以前ズレが発生した理由、完成図の確認方法、今後の追加・修正手順をまとめたものです。

## 1. 現在の作成方法

キャラクターは、球体本体・顔・影を同じキャラクター用グループに入れて作成しています。移動、跳ねるアニメーション、移動方向への向き変更はこのグループに適用されるため、球体と顔の位置が別々にずれない構成です。

| ファイル | 役割 |
| --- | --- |
| [`CountryBall.tsx`](../src/scene/residents/CountryBall.tsx) | 球体、顔、影、移動・跳ね・向き変更を組み立てる |
| [`sphereFlagMaterial.ts`](../src/scene/residents/sphereFlagMaterial.ts) | 球体表面に国旗模様を描画するマテリアル |
| [`flagPresentation.ts`](../src/scene/residents/flagPresentation.ts) | 国旗パターンの判定ルールと共有寸法を定義する |
| [`countries.ts`](../src/game/data/countries.ts) | 国ごとの色と国旗パターンを定義する |
| [`CharacterShowcase.tsx`](../src/dev/CharacterShowcase.tsx) | キャラクターだけを固定位置で確認する開発用画面 |
| [`FlagPresentation.test.ts`](../tests/FlagPresentation.test.ts) | 国旗パターンの判定ルールを自動検証するテスト |

### 球体と国旗の関係

国旗は球体の前面に別画像を貼っていません。`MeshStandardMaterial` にシェーダー処理を追加し、球体のローカル座標から表面の色を決めています。このため、球体が移動・回転しても国旗模様は球体表面から離れません。

現在の主な寸法は次のとおりです。

- 球体半径: `0.48`
- 日本の赤丸の中心: ローカル座標の `y = 0.1`
- 日本の赤丸の半径: `0.28`
- イタリアの縦区切り: `x = -0.16` と `x = 0.16`

国旗パターンは、球体の正面をローカル座標の `z` が正の方向として判定します。

- ポーランド: ローカル `y` の上半分・下半分で色を分ける
- 日本: 正面側の円形範囲だけを赤にする
- イタリア: 正面から見て左を緑、中央を白、右を赤にする

日本の赤丸は球面上の同じマテリアルから描画されるため、正面確認画面では円になります。斜めや真横から見た場合は、球体の曲面に沿って一部が隠れたり、見かけ上つぶれて見えたりすることがあります。これは平面画像のズレではなく、球体を斜めから見た結果です。

### 国ごとの設定

国ごとの色とパターンは [`countries.ts`](../src/game/data/countries.ts) の `colors` と `flagPattern` で管理します。

| 国 | パターン | 正面から見た配色 |
| --- | --- | --- |
| ポーランド | `horizontal` | 上が白、下が赤 |
| 日本 | `circle` | 白地の中央に赤丸 |
| イタリア | `vertical` | 左が緑、中央が白、右が赤 |

## 2. 以前ズレが発生した原因

以前は、球体本体とは別の前面用 `Sprite` に国旗画像を表示していました。この方式では、次の要素が別々に計算されます。

1. 球体の3D位置・回転・陰影
2. カメラ正面を向く平面Spriteの位置・大きさ
3. キャラクターの移動方向と跳ねるアニメーション

そのため、斜め視点、スマートフォンの縦画面、移動中の回転などで、国旗だけが横にずれる、球体から浮く、円がだ円に見えるといった問題が起きやすい状態でした。ポーランドのような球全体の模様は問題が目立ちにくく、日本やイタリアの前面模様でズレが明確になりました。

現在は前面用Spriteを使わず、球体自身のマテリアルで色を決める方式に統一しています。

## 3. 完成図の確認方法

### A. キャラクター確認画面を最初に見る

Cloudflare Pagesへデプロイした後、次のURLを開きます。

[キャラクター表示確認画面を開く](https://countryballstown.pages.dev/?showcase=characters)

ローカルでは、プロジェクトのルートで次を実行し、表示されたポート番号に置き換えて開きます。

```text
npm.cmd run dev
http://localhost:<ポート番号>/?showcase=characters
```

この画面は通常のゲームとは別の開発用表示です。建物や地形の影響をなくし、ポーランド・日本・イタリアを固定位置に並べ、正面から同じ大きさで比較できるようにしています。URLに `showcase=characters` がない場合は、通常のゲーム画面が表示されます。

### B. 固定表示で確認する項目

スマートフォン相当の幅（目安 `390x844`）と、デスクトップ相当の幅（目安 `1280x720`）の両方で確認します。

- ポーランドが上白・下赤になっている
- 日本の赤丸が顔の横ではなく、球体の正面中央にある
- 日本の赤丸が正面から見て円形になっている
- イタリアが正面から見て左緑・中央白・右赤になっている
- 国旗模様が球体から浮いていない、継ぎ目がずれていない
- 目と口などの顔が球体の前面にあり、国旗模様の判定位置と干渉していない
- 3体の大きさ、影、接地位置が不自然でない
- ブラウザの開発者コンソールにエラーがない

固定表示でズレがあれば、通常ゲームの移動やカメラの問題と切り分けて、まず国旗マテリアルと座標ルールを修正します。

### C. 通常ゲーム内で確認する

固定表示が問題なければ、通常URLで次を確認します。

- スワイプまたはドラッグした方向へ移動する
- 移動方向に顔が向く
- 移動中もボールのように跳ねる
- 移動・回転・跳ねの途中で国旗模様が球体からずれない
- 花などの通過可能なオブジェクトは通過できる
- 家などの通過不可オブジェクトは通過できない
- 建物や樹木の背後に入ったとき、奥行き順が自然である
- 斜め・側面から見たときに、球面に沿って国旗の一部が隠れることを確認する

側面表示でイタリアの色が3分割に見えない、日本の赤丸が一部しか見えない、といった現象は、球体を横から見た場合には正常です。正面の配色そのものを判定する基準は、開発用固定表示です。

## 4. 自動確認

プロジェクトルートで次を実行します。

```text
npm.cmd test -- --run
npm.cmd run lint
npm.cmd run build
```

`FlagPresentation.test.ts` では、少なくとも次のルールをコードとして固定しています。

- 日本が `circle` パターンとして扱われる
- イタリアが `vertical` パターンとして扱われる
- イタリアのローカル `x` 座標が、左・中央・右の3色に正しく対応する

表示変更では、自動テストだけで完了にせず、必ずキャラクター確認画面を目視します。自動テストは座標ルールの間違いを検出し、固定表示は実際の球体・シェーダー・顔・照明の組み合わせを検出する役割です。

## 5. 今後の追加・修正ルール

新しい国を追加するときは、まず [`countries.ts`](../src/game/data/countries.ts) に色と既存パターンを登録します。既存の `horizontal`、`circle`、`vertical` で表現できない国旗の場合は、次の順で変更します。

1. `FlagPattern` の型を追加する
2. `getSphereFlagColorIndex` にローカル座標の判定ルールを追加する
3. `sphereFlagMaterial.ts` のシェーダーにも同じ判定を追加する
4. 判定ルールの自動テストを追加する
5. `CharacterShowcase.tsx` で正面表示を確認する
6. 通常ゲーム内で移動・回転・側面表示を確認する
7. lint、test、buildを実行してからコミット・プッシュする

国旗を球体の前に別Spriteとして追加する場合は、球体との位置・回転・縮尺を同期する設計と、その正面・斜め・移動中の確認結果をこの資料に追記してください。基本方針は、現在の球体表面マテリアル方式を継続することです。

## 6. 確認用ファイルの役割分担

```text
国の色・パターン
        ↓
flagPresentation.ts  ── 座標ルールの自動テスト
        ↓
sphereFlagMaterial.ts ── 球体表面への実描画
        ↓
CountryBall.tsx      ── 顔・影・移動・跳ね・回転との組み合わせ
        ↓
CharacterShowcase.tsx ── 固定位置の目視確認
        ↓
通常ゲーム画面      ── 実際の操作・障害物・カメラ確認
```

この順番で確認すると、「国旗の座標ルールの問題」「球体への描画の問題」「移動やカメラとの組み合わせの問題」を分けて調査できます。

## 7. モーションの確認方法

今回追加した自律モーションは、次の開発用URLでまとめて確認できます。

[モーション表示確認画面を開く](https://countryballstown.pages.dev/?showcase=motions)

この画面には、固定位置に次のモーションを配置しています。

- ぼーっとする
- 木を見る
- 噴水を見る
- 建物を利用する
- 喜ぶ
- 寝る
- たまに転ぶ
- 2人で会話する
- 近づいてハートが出る

モーションの状態処理は [`ResidentSystem.ts`](../src/game/systems/ResidentSystem.ts)、球体の姿勢・跳ね・転倒処理は [`CountryBall.tsx`](../src/scene/residents/CountryBall.tsx)、吹き出し・睡眠マーク・ハートなどの演出は [`ResidentMotionEffects.tsx`](../src/scene/residents/ResidentMotionEffects.tsx) に分かれています。確認画面自体は [`MotionShowcase.tsx`](../src/dev/MotionShowcase.tsx) です。

通常ゲームでは、住民が一定時間ごとに行動を選びます。木・噴水・建物へ歩いて向かう行動は、目的地に到着してから注視または利用を開始します。住民同士の行動は、近づく、会話する、会話終了後にハートを出す、という順番です。転倒は低い確率で発生し、一定時間後に通常状態へ戻ります。

## 8. オブジェクトごとの通過・衝突範囲

住民の衝突判定は、建物の中心座標だけではなく、[`BuildingDefinition`](../src/game/types/Building.ts) の次のパラメータで管理します。

- `residentCollision: "blocking"`: 住民が通過できない
- `residentCollision: "passable"`: 住民が通過できる
- `residentCollisionPadding: { x, z }`: グリッド占有範囲から外側へ広げる禁止範囲。オブジェクトの見た目とボール半径に合わせて個別に設定する

現在の設定は、家・噴水・木・ピザ屋が個別の禁止範囲を持ち、温泉・花・鳥居は通過可能です。新しいオブジェクトを追加するときは、まず3Dモデルの外周と住民ボールの半径を確認し、`residentCollisionPadding` を個別に決めます。値を省略した場合は、互換用の小さい既定値が使われます。

確認は [`ResidentSystem.test.ts`](../tests/ResidentSystem.test.ts) で、花と温泉は通過できること、家は十分手前で止まることを自動検証します。画面では、家の屋根・壁・噴水の縁にボールがめり込まないことを、斜め視点でも目視します。
